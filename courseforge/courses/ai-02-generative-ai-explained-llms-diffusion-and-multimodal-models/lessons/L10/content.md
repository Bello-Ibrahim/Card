# L10 Designing a Fair Comparison

Course: AI-02 · Module: M3 · Objectives: O6, O7 · Video: 5 min

## Hook
A colleague says, "Tool A is much better than Tool B. I tried both last week." But did they give both tools the same task? The same prompt? Did they decide in advance what "better" means? Without a fair test, a comparison is only an opinion.

## Explanation
In this module you will compare three generative AI tools on one real task from your work or studies. This is your capstone. Before you run anything, you need to design a **fair comparison**. A fair test has four features.

**1. The same task.** Every tool does exactly the same job, such as "summarise this meeting transcript for my manager" or "create a poster image for a community event".

**2. The same input.** Every tool gets the same source material: the same document, the same photo or the same data. Remove personal or confidential information from the input before you start, and use a hypothetical or public version if needed.

**3. The same prompt.** Write the prompt once and copy it exactly into each tool. If you change the prompt for one tool, you are testing your prompt, not the tool. If a tool needs a different setting (for example, an aspect ratio), write down the difference.

**4. Criteria decided in advance.** Decide how you will judge the results **before** you see them. If you decide afterwards, it is easy to choose criteria that favour the tool you already like.

To judge results, build a simple **scoring rubric** with 4–6 criteria. Useful criteria for most tasks are:

- **Accuracy:** Are the facts, numbers and details correct?
- **Usefulness:** Does the output do the job it was made for?
- **Clarity:** Is it easy to read or understand?
- **Speed:** How long did the tool take, including waiting?
- **Effort to fix:** How much editing would it need before you could use it?

For each criterion, write what a score of 1, 3 and 5 means, so your scoring stays consistent. You can give more weight to the criteria that matter most for your task.

Finally, **record the tool version and the date** of each test. Generative AI tools change often: the model behind a free tool may be updated without notice. A result from one month may not be true the next. Your report is only fair if the reader knows exactly what you tested and when. [VERSION]

**Analogy:** A fair comparison is like a cooking competition. Every cook gets the same ingredients, the same recipe card and the same time. The judges agree on the scoring before they taste anything: flavour, presentation and cooking skill. If one cook got better ingredients, or the judges changed the rules after tasting, the result would mean nothing.

## Worked Example
Ingrid is a public health student in Bergen, Norway. For her capstone, she chooses a real task from her studies: turning a four-page public research summary into a one-page plain-language fact sheet for community members.

- **Task:** "Create a one-page plain-language fact sheet from this summary."
- **Input:** a public summary with no personal data. She saves it as one file to paste into each tool.
- **Prompt:** "You are writing for adults with no medical training. Using only the text below, write a one-page fact sheet with a title, five key points and one 'What you can do' section. If something is not in the text, do not add it."
- **Tools:** three free text tools. [VERSION]

Her rubric, decided before testing:

| Criterion | 1 | 3 | 5 | Weight |
|---|---|---|---|---|
| Accuracy | Several errors | One small error | No errors | x2 |
| Plain language | Many technical words | Some technical words | Clear for all readers | x1 |
| Follows structure | Structure missing | Partly followed | Fully followed | x1 |
| Effort to fix | Needs rewriting | Some editing | Ready to use | x1 |

She gives accuracy double weight, because a fact sheet with wrong health information could cause harm.

## Common Mistake
Many learners improve the prompt while testing, for example after the first tool gives a weak answer. Then the second and third tools get a better prompt, and the comparison is no longer fair. The correction is to finish the prompt and rubric first, test the prompt once in a separate "trial run" if needed, and then keep them fixed for all three tools.

## Key Takeaways
1. A fair comparison gives every tool the same task, the same input and the same prompt.
2. Decide the scoring criteria before you see any results, and define what low, middle and high scores mean.
3. Record the tool version and the date of every test, because generative AI tools change often.

## Hands-on Exercise
**Task:** Capstone step 1: choose one real task from your work or studies, write the exact prompt and input you will use, and create a scoring rubric with 4–6 criteria.
**Tools:** A document or spreadsheet; the capstone rubric template on the course page.
**Steps:**
1. Choose a real task that you do often and that at least three free tools can attempt. [VERSION]
2. Prepare the input. Remove all personal and confidential data, or create a realistic hypothetical version.
3. Write the exact prompt. Read it once more and fix anything unclear.
4. Create a rubric with 4–6 criteria. For each, describe scores of 1, 3 and 5, and decide the weight.
5. Name the three tools you plan to test and note why you chose them.
6. Save everything in one document for L11.
**What good looks like:** A clear task description, a saved input with no personal data, one fixed prompt, a rubric with 4–6 defined criteria and weights, and a short list of three tools with a reason for each.
**Time:** about 30 minutes
